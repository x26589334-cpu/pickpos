# 설치 후기 (review/) — 양식과 규칙

> 사용자가 **"오늘 후기 써줘"** 하면 이 파일대로 하루 1편을 만들어 발행한다.
> H포스(hpos.co.kr) 블로그 후기와 **같은 구성**으로 간다. 다만 문장은 새로 쓴다.

## 기본 구조 (원본: `review/2026-09-10-pyeongtaek-frozen-vending.html`)

1. **제목(h1)**: `{지역} 무인자판기 설치 — {업종} {특징}`
2. **날짜 줄**: `YYYY.MM.DD · {시도} {지역} · {업종}`
3. **사진 1장** + figcaption
4. **리드 2문단** — 그 지역·업종에 왜 이 구성이 맞는지, 현장에서 먼저 보는 것(전원·수평·동선)
5. **h2 {지역} {업종}에 맞는 구성** — 장비 구성, 결제 수단, 원격 관리
6. **h2 좋은 점과 어려운 점** — 장점 먼저, 단점도 솔직히. 과장 금지
7. **h2 {지역} 무인매장, 이런 자리가 잘 됩니다** — 그 지역 실제 지명·기관·상권
8. **h2 {지역} 서비스 지역** — `.dong-line` 박스에 동·읍면 대량 + 인접 시군
9. **h2 {지역} 무인창업, 이렇게 시작하시면 됩니다** — 설치비 무료, 구입이 유리, 계산기 링크
10. **CTA** — 전화 + 견적 폼
11. **`.kw-box` 함께 많이 찾는 키워드** — 25~30개. 지역 × (자판기·포스기·카드단말기·키오스크) 조합
12. **주석** — 사진 출처 문구(아래 참고)
13. **관련 링크**

분량: 본문 1,200~1,600자. 소제목 5~6개.

## 사진 — 순번대로 하나씩

- 원본: `C:\Users\DOJIVERSE\Desktop\바인\자판기 사진` (저장소 밖. 커밋하지 않는다)
- 순번표: **`_content/사진목록.tsv`** — 492장에 1번부터 번호가 매겨져 있다
- **N회차 후기 = 사진 N번.** 전날과 겹치지 않게 순번을 그냥 따라간다
- 폴더 이름의 지역은 **무시한다.** 사진은 채워 넣는 용도이고 글의 지역은 아래 목록에서 따로 고른다
- 다만 **사진에 보이는 장비에 업종을 맞춘다** — 냉동 쇼케이스 사진이면 무인정육점·밀키트, 냉장 자판기면 음료·스낵, 키오스크가 보이면 무인매장. 사진과 글이 어긋나면 티가 난다
- 발행 전 **사진을 반드시 열어서 확인**한다. 사람 얼굴·상호·간판이 크게 나온 사진은 건너뛴다
- 웹용으로 줄여서 쓴다 (원본은 3~5MB):
  ```
  powershell -ExecutionPolicy Bypass -File _content\사진줄이기.ps1 `
    -Src "원본 절대경로.jpg" -Out "2026-09-11-지역.jpg"
  ```
  → `photos/review/` 에 긴 변 1200px, 100~150KB 로 저장된다

### ⚠️ 사진 출처 문구 (반드시 넣는다)
사진의 실제 장소와 글의 지역이 다르므로, 글 하단 `.art-note` 에 이 문장을 넣는다.
> ※ 사진은 픽포스가 시공한 설치 사례이며, 글에 적힌 지역의 현장 사진은 아닙니다.

figcaption 에도 **"{지역}에 설치한"** 이라고 쓰지 않는다. `"…구성입니다. 픽포스가 시공한 설치 사례입니다."` 형태로 쓴다.
(사진 자체는 전부 픽포스가 직접 시공한 실제 현장이라 저작권 문제는 없다)

## 지역 — 목록 순서대로

`_content/후기지역목록.md` 의 위에서부터. 이미 쓴 지역은 ✅ 표시.
같은 지역이 다시 돌아오면 **업종을 바꿔서** 쓴다 (평택 무인정육점 → 평택 공장 → 평택 병원).

## 발행 절차
1. `git status` 깨끗한지 → `git pull --ff-only`
2. `_content/후기지역목록.md` 에서 다음 지역, `_content/사진목록.tsv` 에서 다음 사진 번호를 고른다
3. **사진을 열어 확인** → 업종 결정 → 축소 스크립트 실행
4. `review/{YYYY-MM-DD}-{지역영문}-{업종영문}.html` 작성 (원본 복사 후 전부 교체)
   - title · description · keywords · canonical · og · twitter · JSON-LD 3개(BlogPosting·Breadcrumb) 전부 새 지역으로
5. `review/index.html` 맨 앞에 카드 1개 추가
6. `sitemap.xml` 에 url 추가 (priority 0.6, changefreq monthly)
7. 두 목록 파일에 ✅ 와 사용한 사진 번호 기록
8. 헤드리스 크롬으로 스크린샷 1장 찍어 깨진 곳 확인
9. `git add -A` → 커밋 `후기 추가: {지역} {업종}` → `git push`
10. `사이트관리/작업로그.md` 맨 위에 완료 한 줄

## 발행 전 체크
- [ ] 사진을 직접 열어봤다 (얼굴·상호 노출 없음)
- [ ] 사진 번호를 사진목록.tsv 에 기록했다 (중복 방지)
- [ ] `.art-note` 에 사진 출처 문구가 있다
- [ ] figcaption 이 지역을 단정하지 않는다
- [ ] 지역 문장이 이전 글과 다르다 (지명·기관·상권을 실제로 언급)

- [ ] canonical / og:url / JSON-LD url 셋 다 새 파일명
- [ ] 경로가 전부 `../` (review/ 안이므로)
